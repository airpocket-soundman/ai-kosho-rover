## 決定の記録

| 日付 | 決定 | 理由 |
| --- | --- | --- |
| 2026-09-24 | 駆動は Geekservo DC モーター、フレームは LEGO | 入手しやすく、組み替えが容易 |
| 2026-09-24 | 搬送は台の下に潜って持ち上げる方式 | アームを使わず機構を単純化 |
| 2026-09-24 | 車輪エンコーダーは使わない | Geekservo にエンコーダーがなく、メカナムは滑りが大きいため |
| 2026-09-24 | LAYA は高レベル行動の選択に限定し、速度指令は機体側の制御 | LAYA の出力は離散の型付き判断で、連続値を出せないため |
| 2026-09-24 | 自己位置は LD06 + 事前地図 + 床面フロー + IMU でローバー単独推定 | 走行領域を俯瞰できるカメラ位置がなく、標識も貼らないため。LD06 は手持ち |
| 2026-09-24 | 床面フローセンサーは PAA5100JE を採用、先行実験用の PMW3901 は AliExpress で購入 | 動作距離 15〜35 mm と内蔵 LED が条件に合う。秋月・スイッチサイエンスに取り扱いなし |
| 2026-09-24 | 電子音を「小姓語」として言語体系化し、デコーダー / 合成器アプリをサイトに置く | 裏設定として一貫させ、家族や来客が翻訳して遊べるようにするため |
| 2026-09-24 | LAYA は自宅 PC のサーバーで実行、画像は送らない | UNO Q では遅く、PC の GPU なら数十 ms。家庭内 LAN にとどめる |
| 2026-09-24 | ドッキングと接近を模倣学習で置き換える(古典制御はフォールバック) | 企画の Physical AI の狙いを機体側に残すため |
| 2026-09-24 | 台は LEGO の色と収納位置で識別 | 標識を貼らないため |
| 2026-09-24 | LD06 は中段搭載。リフト板の柱 4 本は斜め 45° 方向に置き、死角はマスク処理 | 最上部に置けない構造のため。前後左右の視野を優先 |
| 2026-09-24 | 待機位置は充電ステーション。待機中も常時 Wi-Fi で玄関を監視 | 常時稼働が前提のため。待機中は LD06 を止めて寿命を守る |
| 2026-09-24 | 意思表示は言葉でなく R2-D2 風の電子音(DFPlayer Mini) | 話しかけなくてよい設計に合わせ、短い合図で伝える |
| 2026-09-24 | 下半身視点の検出モデルを自作 | ローバーカメラには上半身が映らないため |
