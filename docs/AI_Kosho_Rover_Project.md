# AI小姓ローバー（仮）企画書

## 1. コンセプト

Arduino UNO系ボード上で動作するPhysical
AIとして、家庭の玄関・廊下で人間の行動を常時観察し、次に必要になる行動を予測して「少しだけ先回りして手伝う」小型メカナムローバーを製作する。

モチーフは、羽柴秀吉（藤吉郎）が織田信長の草履を懐で温めておいたという有名な逸話。命令を受けてから動くのではなく、相手の状況や次の行動を察して準備する「現代のAI小姓」を目指す。

単なるルールベースの自動搬送ではなく、JEV系の汎用Decision
Model、特にローカル実行可能なLAYAの利用を検討し、人間の行動理解からローバー自身の身体制御まで可能な限りAIに担当させる。

------------------------------------------------------------------------

## 2. 利用環境

主な活動範囲は家庭内の以下の場所とする。

-   玄関ホール
-   廊下
-   玄関付近の収納スペース

玄関・廊下は家具や障害物が比較的少なく、小型ローバーが走行しやすい。また、人間の行動が「外出」「帰宅」「通過」などに集約されるため、行動予測の対象としても扱いやすい。

------------------------------------------------------------------------

## 3. 基本シナリオ

### 3.1 外出時

ローバーは待機中も周囲の人間を観察する。

1.  父・母・子など人物を識別する。
2.  廊下から玄関へ向かう動作などを観察する。
3.  靴を履く、荷物を持つ、玄関扉へ向かうなどの時系列的な兆候から「外出」を予測する。
4.  対象人物専用の小物トレーを収納場所から運ぶ。
5.  財布、腕時計、車の鍵などをトレーごと差し出す。
6.  天気・気温などに応じて傘、帽子など追加で必要な物を準備する。
7.  人が必要な物を取る。
8.  玄関扉が閉まり、本当に外出したことを確認する。
9.  空になったトレーや残った物を収納場所へ戻す。
10. ローバー自身もホームポジションへ戻る。

### 3.2 帰宅時

1.  玄関扉が開く。
2.  帰宅した人物を識別する。
3.  帰宅と判断したら、その人物用の空トレーを持って迎えに行く。
4.  財布、腕時計、車の鍵などをトレーで受け取る。
5.  人物が玄関から離れたことなどから受け取り完了を判断する。
6.  トレーを所定の収納場所へ運ぶ。
7.  トレーを降ろす。
8.  ローバーはホームポジションへ戻る。

------------------------------------------------------------------------

## 4. 「察する」ための観測

一つの認識結果だけで行動を決定せず、複数の兆候を時系列として扱う。

### 人物に関する観測

-   父・母・子などの人物識別
-   人物の位置
-   移動方向
-   身体の向き
-   姿勢
-   玄関方向への接近
-   靴を履く／脱ぐ動作
-   屈む、立ち上がるなどの動作
-   荷物を持っているか
-   玄関から退出したか

### 環境に関する観測

-   玄関扉の開閉
-   時刻
-   天気
-   降雨
-   気温
-   必要に応じて日射・UV等
-   トレーの有無
-   トレー上の荷物の有無／重量

### 時系列の例

``` text
t-5s : father detected, hallway
t-4s : moving toward entrance
t-3s : stopped near shoes
t-2s : bending down
t-1s : interacting with shoes
now  : standing near door
weather : rain
father tray : stored
```

このような状態系列からDecision Modelが次の行動を判断する。

------------------------------------------------------------------------

## 5. Decision Model / JEV / LAYA

本企画では、可能であればLAYAなどのローカル汎用Decision
ModelをArduino上で動作させる。

目標は単なる高レベルタスク選択だけではなく、ローバーの身体制御までDecision
Modelに担当させること。

### 入力候補

-   カメラ画像または視覚特徴量
-   人物認識結果
-   人物行動の時系列
-   ToF距離情報
-   IMU
-   ホイールエンコーダ
-   推定自己位置
-   ドア状態
-   トレー状態
-   天候・気温
-   過去のAction

### 高レベルAction例

``` text
WAIT
GET_FATHER_TRAY
GET_MOTHER_TRAY
GET_CHILD_TRAY
BRING_UMBRELLA
BRING_HAT
RECEIVE_ITEMS
STORE_TRAY
RETURN_HOME
OBSERVE_FROM_ANOTHER_POSITION
```

### 身体制御

可能であればDecision Modelから直接、

``` text
vx
vy
omega
lift
```

などを出力する。

メカナムホイール固有の運動学変換のみ固定処理として、

``` text
JEV / Decision Model
        ↓
   vx, vy, omega
        ↓
Mecanum kinematics
        ↓
 four wheel motors
```

とする。

これにより「何をするか」と「身体をどう動かすか」を可能な範囲で同じAIに担当させる。

------------------------------------------------------------------------

## 6. Active Perception

判断に必要な情報が不足している場合、ローバー自身が観測位置を変更する。

例：

``` text
父が玄関方向へ移動
        ↓
外出か宅配対応か判断できない
        ↓
ローバーが横移動
        ↓
玄関が見える位置へ移動
        ↓
靴を履いていることを確認
        ↓
外出と判断
        ↓
父用トレーを取りに行く
```

「見えないから分からない」で終了するのではなく、「分からないから見に行く」という能動知覚をPhysical
AIの重要な要素とする。

------------------------------------------------------------------------

## 7. 移動機構

### メカナム4輪ローバー

全方向移動可能な小型メカナムローバーを採用する。

利点：

-   廊下で方向転換せず横移動できる
-   人への受け渡し位置を細かく調整できる
-   トレー下へのドッキングが容易
-   観測位置を横方向へ変更しやすい
-   狭い玄関で姿勢を保ったまま移動できる

------------------------------------------------------------------------

## 8. 自己位置推定と周囲認識

本格的なVisual SLAMを必須とはしない。

玄関・廊下という限定された既知環境を利用し、軽量な自己位置推定を行う。

### センサー融合

``` text
Wheel Encoder ─┐
IMU ──────────┼─→ Localization → x, y, theta
ToF ──────────┤
Camera ────────┘
```

### 基本方針

-   Encoder + IMU：短時間のDead Reckoning
-   ToF：壁との距離による位置補正
-   Camera：ランドマークや環境認識
-   必要ならAprilTag等：絶対位置補正

地図は10 cm程度の粗いOccupancy Gridでもよい。

毎回SLAMするのではなく、事前に作成した玄関・廊下の地図を保存し、通常運転ではLocalizationを主体とする方法も検討する。

------------------------------------------------------------------------

## 9. 近接・衝突防止

メカナムは横方向にも移動するため、前方だけでなく360°の近接情報が必要。

### ToF

前後左右、可能なら斜め方向も含めて距離を取得する。

候補：

-   単点ToF × 4～8
-   Multi-zone ToF × 複数

Multi-zone ToFなら低解像度Depth
Mapとして利用でき、カメラほど情報量を増やさず周囲形状を取得できる。

### AIへの入力

ToF情報もDecision Modelへ入力し、

-   壁沿い走行
-   障害物回避
-   人への接近
-   トレーへのドッキング
-   センタリング

などの身体制御に利用する。

### Safety Layer

AIとは別に最終的な衝突防止機構を持つ。

例：

``` text
ToF < safety threshold
        ↓
Emergency Motor Stop
```

さらに外周バンパースイッチを設け、ToFが検出しにくい対象への接触も検知する。

通常走行はAIが担当し、Safety Layerは非常時のみ介入する。

------------------------------------------------------------------------

## 10. トレー方式による荷物受け渡し

ロボットアームは使用せず、交換可能なトレー方式を基本とする。

### 収納例

``` text
┌─────────────────────┐
│ 父 │ 母 │ 子 │ 傘 │ 帽子 │
├─────────────────────┤
│      各種トレー       │
├─────────────────────┤
│       Rover          │
│   Charging Station   │
└─────────────────────┘
```

### トレー取得

ローバー上面に小型リフトを搭載する。

1.  トレー下へ潜り込む。
2.  メカナムで位置を微調整する。
3.  リフトを数mm上昇。
4.  トレーを持ち上げる。
5.  人のところまで運搬。
6.  必要に応じてトレーを降ろす。

ロボットアームを使わないことで機構を単純化する。

------------------------------------------------------------------------

## 11. トレーの状態検出

トレーまたはローバーのリフト部に重量センサーを設置する案を検討する。

例：

``` text
0 g
 ↓
財布・鍵・時計を置く
 ↓
280 g
 ↓
「荷物を受け取った」と判断
```

カメラによる物体認識と重量情報を組み合わせれば、受け渡し完了判定を安定させられる。

------------------------------------------------------------------------

## 12. Physical AIとしての狙い

本企画では単なる、

``` text
人物認識 → if文 → 自動搬送
```

にはしない。

目標は、

``` text
Observe
   ↓
Predict
   ↓
必要なら自分で見に行く
   ↓
Decide
   ↓
Move / Manipulate
   ↓
Observe Result
   ↓
次のDecision
```

という閉ループを実世界で成立させること。

特に、

-   人間の次の行動を予測する
-   介入する必要があるか判断する
-   不確実なら観測位置を自ら変える
-   周囲との距離を身体感覚として利用する
-   自分自身の移動もAIで制御する
-   行動後の環境変化を確認する

という点をPhysical AIの中心とする。

------------------------------------------------------------------------

## 13. 作品としての象徴

コンセプトは「現代のAI小姓」。

羽柴秀吉が信長の草履を温めていたという有名な逸話のように、命令を受けてから動くのではなく、

> 相手を観察し、次に何が必要になるかを察し、少しだけ先回りして準備する。

ことをロボットで実現する。

利用者はロボットへ話しかけたり、アプリを操作したり、ボタンを押したりする必要がない。

普通に生活していると、必要なときだけローバーが現れる。

## 16. 企画の中心となる問い

> **汎用Decision
> Modelに小さな身体を与えたとき、人間の行動を観察して次に必要なことを予測し、移動・観測・物理的支援まで自律的に行えるか？**

単なる「ArduinoでAIを動かす」作品ではなく、知覚・予測・意思決定・身体制御・環境との相互作用を一つのループとして実装するPhysical
AIを目標とする。
