ローバーの前方カメラは床上 8〜10 cm にあり、人の上半身は映りません。この視点に特化した検出モデルを作るために、画像を自分たちで収集し、本人がラベリングします。既存の人物検出モデルは全身・上半身を前提にしているため、この視点では精度が出ない前提で進めます。

## 1. モデルに求めること

| 目的 | 検出したいもの | 使い方 |
| --- | --- | --- |
| 外出の兆候 | 靴を履いた足、床に置かれた靴、しゃがんだときの手、荷物 | 「靴を履いている」「荷物を持っている」を時系列に記録 |
| 帰宅の兆候 | 靴を脱ぐ動作(靴 → 靴下)、扉の隙間 | 玄関での受け取りタイミング |
| 安全 | 足の位置と距離 | 30 cm 以内で減速、接近方向の判断 |
| ドッキング | 台の脚 | AprilTag が読めないときの補助 |

## 2. クラス定義(初版)

| クラス名 | 定義 | ラベリングの注意 |
| --- | --- | --- |
| `feet_shoes` | 靴を履いた足(片足ごと) | 靴の全体を囲む。足首まで入れてよい |
| `feet_socks` | 靴下の足(片足ごと) | 同上 |
| `feet_bare` | 素足(片足ごと) | 同上 |
| `shoe_on_floor` | 床に置かれた、履かれていない靴 | 片方ずつ。足が入っていれば `feet_shoes` |
| `hand_low` | 床から 40 cm 以下にある手 | しゃがみ・靴の着脱の手がかり |
| `bag` | 手提げ・リュック・買い物袋 | 床に置かれたものも含む |
| `umbrella` | 傘(畳んだ状態) | 持っているもの、立てかけたもの両方 |
| `stand_leg` | 台の脚 | 見えている脚を 1 本ずつ |
| `door_gap` | 玄関扉の開いた隙間(外光が見える領域) | 閉まっていれば付けない |

判断のルール:

- 見切れていても 3 割以上見えていれば付ける。
- 迷ったら付けない(偽陽性より欠落を優先)。迷った画像はファイル名を `review/` に記録して後で見直す。
- クラスの追加・統合は 300 枚ラベリングした時点で一度見直す。

## 3. 収集手順

| 項目 | 内容 |
| --- | --- |
| カメラ | ESP32-CAM(OV2640)。ローバー完成前は同じ高さ(8〜10 cm)の簡易台に固定 |
| 解像度 | 640×480、JPEG。学習時に 320×320 へ縮小 |
| 保存 | UNO Q または PC で MJPEG を受け、1 秒に 1 枚を保存。人が映ったときだけ保存する動体検出をかける |
| 場所 | 玄関(靴を履く位置)、廊下(接近)、収納スペース(台) |
| 時間帯 | 朝(外出)、夕方〜夜(帰宅)を中心に、昼の自然光も含める |
| 変化 | 家族全員、服装(スリッパ・裸足・靴下・各種靴)、荷物の有無、照明の ON/OFF |
| 負例 | 誰もいない、ペット、荷物だけ、掃除機など |

目標枚数(初版):

| 段階 | 枚数 | 用途 |
| --- | --- | --- |
| 第 1 回 | 300 枚 | クラス定義の検証、最初の学習 |
| 第 2 回 | +700 枚(合計 1,000 枚) | 本番用モデル |
| 継続 | 月 200 枚 | 誤検出した場面の追加(hard example) |

ファイル名は `YYYYMMDD_HHMMSS_<場所>_<カメラ>.jpg` とし、撮影条件をメタデータ(CSV)に残します。

## 4. ラベリング

| 項目 | 内容 |
| --- | --- |
| ツール | Label Studio(ローカル実行)または X-AnyLabeling。どちらも YOLO 形式で書き出せる |
| 形式 | YOLO 形式(`class cx cy w h`、正規化座標)。`classes.txt` にクラス順を固定 |
| 分割 | 撮影日単位で train / val / test = 70 / 15 / 15 に分ける(同じ場面が両方に入らないようにする) |
| 品質確認 | 100 枚ごとに 10 枚を抜き取り、自分で再ラベリングして一致を確認 |
| 担当 | ラベリングは本人。クラス定義の見直しは相談して決める |

半自動化: 第 1 回の 300 枚で学習したモデルの推論結果を初期ラベルとして読み込み、修正だけ行うことで第 2 回以降の作業を減らします。

## 5. 学習と配備

| 項目 | 内容 |
| --- | --- |
| モデル | YOLO 系の最小モデル(YOLOv8n または YOLO11n 相当)、入力 320×320 |
| 学習環境 | 自宅 PC(NVIDIA GPU、CUDA 13)。事前学習済み重みから微調整 |
| データ拡張 | 明るさ・コントラスト、左右反転、軽い回転、モザイク |
| 変換 | ONNX(opset 17)、int8 量子化を試す |
| 実行 | UNO Q の Linux 側で ONNX Runtime(CPU)。目標 5 fps 以上、メモリ 300 MB 以下 |
| 代替 | Edge Impulse で FOMO / YOLO を学習し、App Lab の Video Object Detection Brick として配備 |

評価指標:

| 指標 | 目標 |
| --- | --- |
| mAP50(検証セット) | 0.7 以上 |
| `feet_shoes` と `feet_socks` の混同率 | 10 % 以下 |
| UNO Q での推論速度 | 5 fps 以上 |
| 実環境の「靴を履いた」検出遅れ | 2 秒以内 |

## 6. プライバシーと保管

- 画像はリポジトリに入れない(`.gitignore` の `data/`、`captures/` で除外済み)。PC の暗号化ドライブに保管する。
- 家族に撮影の目的と範囲を説明し、同意を得てから収集する。
- 公開するのは、ぼかし処理をした少数の例と統計値だけにする。
- 収集した画像は本プロジェクトの学習以外に使わない。

## 7. データ構成

```text
data/                      (git 管理外)
├── raw/                   撮影した元画像
│   └── 20261005_entrance_cam1/
├── labeled/               YOLO 形式
│   ├── images/{train,val,test}/
│   ├── labels/{train,val,test}/
│   └── classes.txt
├── review/                判断に迷った画像のリスト
└── meta.csv               撮影日時・場所・照明・人物(匿名 ID)
models/                    (git 管理外)
└── lowerbody_v1.onnx
```

学習スクリプトと設定ファイルはリポジトリに置き、データと学習済みモデルは置きません。
